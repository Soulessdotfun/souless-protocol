# Security Policy

Souless welcomes responsible security reports.

If you believe you have found an exploitable vulnerability, **do not open a public issue with reproduction details or active exploit instructions**.

Use GitHub's private vulnerability reporting / Security Advisory flow for this repository when it is available. If that option is unavailable, contact the Souless maintainers through the official channels linked from [souless.fun](https://souless.fun) and coordinate a private disclosure before publishing details.

Please include:

- the affected contract or component;
- the relevant network and address, if deployed;
- the security impact;
- a minimal reproduction or proof of concept;
- any assumptions required for exploitation.

Public issues are appropriate for non-sensitive correctness, documentation, and integration problems.
